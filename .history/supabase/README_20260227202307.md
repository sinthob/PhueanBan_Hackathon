# Supabase setup (Auth + Postgres)

## 1) Env vars (Expo)

- Copy `.env.example` to `.env`
- Fill values from Supabase Dashboard → Project Settings → API
  - `EXPO_PUBLIC_SUPABASE_URL`
  - `EXPO_PUBLIC_SUPABASE_ANON_KEY`

## 2) Database schema + RLS

- Open Supabase Dashboard → SQL Editor
- Run [schema.sql](schema.sql)

This creates:

- `public.profiles` with `role = elder | caregiver`
- `public.caregiver_elder_links` for caregiver↔elder assignment (future use)

## 3) App auth flow

- Unauthenticated → redirects to `/(auth)/login`
- Signed in but no profile role → redirects to `/(onboarding)/role`
- Role `elder` → redirects to `/(tabs)`
- Role `caregiver` → redirects to `/caregiver`

## 4) (Optional) Chatbot via OpenAI (Edge Function)

Important: Do NOT put your OpenAI API key in Expo `.env` (client). Use the Supabase Edge Function in `supabase/functions/chatbot`.

Setup overview:

- Install Supabase CLI and link your project.
- Deploy the function:
  - `supabase functions deploy chatbot`
- Set secrets on Supabase (Dashboard or CLI):
  - `OPENAI_API_KEY`
  - (optional) `OPENAI_MODEL` (default is `gpt-4o-mini`)

In the app, the Messages tab calls:

- `supabase.functions.invoke('chatbot', { body: { messages } })`

If the function/secrets are not configured yet, the UI will fall back to a friendly offline message.

### Troubleshooting

- `401 {"code":401,"message":"Invalid JWT"}`
  - Ensure the app is using a matching pair of values from the SAME Supabase project:
    - `EXPO_PUBLIC_SUPABASE_URL` like `https://<ref>.supabase.co`
    - `EXPO_PUBLIC_SUPABASE_ANON_KEY` whose JWT payload contains the same `ref`
  - Restart Expo with cache cleared after editing `.env` (Metro can cache env):
    - `npx expo start -c`

## Notes

- Authorization must be enforced by Postgres RLS policies (not only in the app UI).
- If you see `permission denied` errors when loading profiles, re-check that RLS is enabled and policies exist.
